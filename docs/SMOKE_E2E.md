# Smoke E2E — пассажир → водитель → админ

Сценарий приёмки по ТЗ §8 / §9. Без mock: `USE_MOCK_API=false`.

Скрипт-обёртка (чеклист + HTTP health): [`scripts/smoke_e2e.ps1`](../scripts/smoke_e2e.ps1).

---

## Предусловия

| # | Условие |
|---|---------|
| 1 | API доступен (`API_BASE_URL`, HTTPS в prod) |
| 2 | SMS: реальный провайдер **или** известный demo/test OTP только на staging |
| 3 | В prod: `OTP_DEBUG_LOG=0`, demo OTP выключен |
| 4 | Два устройства / эмулятора: пассажир + водитель |
| 5 | Админ: `http(s)://<host>/admin/` + учётные данные |
| 6 | MapKit / geo keys в сборках (иначе карта — premium canvas, не стор-скрин) |

---

## Шаги

### A. Пассажир

1. Онбординг → согласие с политикой / офертой → OTP.
2. Главный экран: геопозиция + поиск «Куда».
3. Тариф → пожелания → способ оплаты (**cash** для smoke без эквайера).
4. Подтверждение → заказ создан → экран активной поездки.
5. Зафиксировать `orderId` (из UI / Network).

### B. Водитель

1. OTP → KYC approved (или тестовый уже верифицированный номер).
2. Online / на линии.
3. Новый заказ в ленте (или push) → **Принять**.
4. Статусы: enroute → arrived → started → complete.
5. Чат (опц.): сообщение видно у пассажира.

### C. Пассажир (завершение)

1. Статус «завершена» → оценка.
2. История поездок содержит заказ.
3. (Если card/SBP включены на сервере) оплата → webhook → paid.

### D. Админ

1. Диспетчерская: заказ виден на всём пути статусов.
2. Клиент и водитель привязаны к заказу.
3. При наличии платежа — запись / статус оплаты.
4. Карта: при lat/lng точек — маркеры; без GPS — grid placeholder (ожидаемо).

## HTTP smoke (минимальный)

```powershell
$base = $env:API_BASE_URL
if (-not $base) { $base = 'http://161.104.19.23' }
Invoke-RestMethod "$base/api/health" -TimeoutSec 15
# Ожидание: 200 / ok payload
```

Полный путь OTP→order требует SMS и токены — выполняйте вручную по шагам A–D или через Postman-коллекцию ops.

---

## Критерии PASS (ТЗ §9)

- [ ] Весь путь без `USE_MOCK_API=true` и без фейковой истории.
- [ ] Админ видит заказ, клиента, водителя.
- [ ] Нет debug OTP в production.
- [ ] Нет видимых «скоро» на primary CTA в этом сценарии.
- [ ] Краши не блокируют flow (см. [MONITORING.md](MONITORING.md)).

## Известные допустимые ограничения на smoke

| Область | Допустимо на smoke | Блокер стора |
|---------|-------------------|--------------|
| Card/SBP | Cash-only, если эквайер не настроен | Обещать онлайн-оплату в сторе нельзя |
| Avatar upload | Цвет аватара (`ENABLE_AVATAR_UPLOAD=false`) | Нет |
| Admin map без GPS | Placeholder grid | Нет, если есть lat/lng у живых заказов |
| Nav map водителя | Premium canvas без MapKit key | Нужен MapKit для стор-скринов |
