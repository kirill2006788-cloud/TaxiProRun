# TaxiProRun / "Короли дорог": полное ТЗ до уровня продукта класса Yandex Go

Дата аудита: 22.07.2026  
Цель: довести пассажирское приложение, приложение водителя, админку и сервер до состояния production-продукта такси/трезвого водителя с UX-уровнем Yandex Go, но со своим брендом, визуальным языком и юридически самостоятельным дизайном.

> Важно: нельзя копировать Yandex Go 1:1 по бренду, иконкам, текстам, фирменным элементам и уникальным визуальным паттернам. Делаем функциональный паритет, скорость, удобство и уровень качества, но в своем стиле "Короли дорог".

## 1. Текущее состояние проекта

В проекте уже есть:

- Flutter-приложение пассажира в корне проекта.
- Отдельное Flutter-приложение водителя в `driver_app`.
- Backend на NestJS в `backend/api`.
- Web-админка в `admin`.
- Реальные APK/AAB-сборки в `release`.
- Основные экраны пассажира: onboarding, маршрут, тарифы, пожелания, оплата, подтверждение, активная поездка, история, профиль, поддержка.
- Основные экраны водителя: вход, регистрация, заказы, активный заказ, история, профиль, настройки, поддержка.
- API: авторизация по OTP, заказы, тарифы, водительские статусы, клиенты, поддержка, оплаты, push-token, Socket.IO события.
- Документация по платежам, push, release readiness и store checklist.

Оценка готовности по коду и документации:

- Пассажирское приложение: примерно 70-75%.
- Приложение водителя: примерно 65-70%.
- Backend API: примерно 70%.
- Админка: примерно 55-60%.
- Production/release/store/monitoring: примерно 45-50%.
- Дизайн-полировка и UX до уровня большого сервиса: примерно 55-60%.

## 2. Главные блокеры до full release

### 2.1. Production-инфраструктура

- Настроить полноценную production-БД: Postgres, миграции, backup, rollback.
- Перенести rate limit из памяти процесса в Redis.
- Настроить Redis для OTP, очередей, активных заказов, геолокации и dispatch.
- Завести staging и production окружения отдельно.
- Настроить CI/CD: analyze, test, build apk/aab/ipa, deploy backend/admin.
- Добавить мониторинг: Sentry/Crashlytics, backend logs, health checks, uptime alerts.
- Настроить безопасное хранение ключей: env/secret manager, без ключей в репозитории.

### 2.2. SMS, Push, Payment

- Включить реального SMS-провайдера для OTP, без debug-кодов в production.
- Добавить `google-services.json` для пассажира и водителя.
- Добавить iOS `GoogleService-Info.plist`.
- Настроить backend service account для FCM.
- Довести push-уведомления: новый заказ водителю, статус заказа клиенту, чат, отмена, прибытие, завершение, промо.
- Подключить реального платежного провайдера: карта, СБП, webhook, возвраты, отмены, чеки.
- Сделать платежи не только UI-флоу, а полноценной финансовой операцией с idempotency key и audit log.

### 2.3. Карты, гео, навигация

- Убрать все placeholder-карты из primary-flow.
- В админке заменить `map-placeholder` на живую карту с водителями и заказами.
- Для водителя сделать полноценную навигацию: маршрут до подачи, маршрут до точки B, reroute, ETA, дистанция, голос/подсказки хотя бы текстовые.
- Для пассажира сделать стабильные подсказки адресов, избранные адреса, недавние адреса, подъезд/комментарий.
- Проверить production-ключи MapKit/Geocoder/Geosuggest/Routing.
- Если Routing API недоступен, явно показывать расчет как предварительный, а не точный.

### 2.4. Удаление заглушек

- Убрать все видимые "скоро" из основных пользовательских сценариев.
- Все mock-данные оставить только за флагом dev/mock.
- В production `USE_MOCK_API=false`.
- Проверить, что история поездок, профиль, заказы, чат, оплаты и поддержка берутся из API.
- Почистить дубли backend-файлов: `*.patched`, `_remote`, `_vps_live`, если они не участвуют в сборке.

## 3. Пассажирское приложение: полное ТЗ

### 3.1. Первый запуск и авторизация

- Splash screen с брендом, без долгой заставки.
- Onboarding на 2-3 экрана максимум: такси, трезвый водитель, безопасность.
- Авторизация по телефону через OTP.
- Повторная отправка кода с таймером.
- Обработка ошибок: неверный код, SMS не пришла, лимит попыток, нет сети.
- После входа: имя, аватар, разрешение геолокации, согласие с политикой.
- Гостевой сценарий можно оставить только для просмотра тарифов, заказ без телефона запрещен.

### 3.2. Главный экран

- Первый экран: полноэкранная карта.
- Нижняя draggable-панель с адресом "Куда едем?".
- Кнопка текущей геопозиции.
- Быстрые адреса: Дом, Работа, Последние.
- Кнопка выбора сервиса: Такси / Трезвый водитель / Доставка, если доставка остается в продукте.
- При фокусе на адресе панель раскрывается в поиск.
- Поиск адреса: подсказки, история, избранное, карта выбора точки.
- Поддержать точку подачи и точку назначения.
- Поддержать несколько точек маршрута.
- Поддержать подъезд, комментарий, "встретить у входа".

### 3.3. Расчет поездки

- После выбора маршрута карта показывает линию маршрута, точки A/B, ETA.
- Панель снизу показывает тарифы горизонтальной каруселью.
- Каждый тариф: название, ближайшая подача, цена, иконка авто, вместимость.
- Для "Трезвого водителя": обязательно выбрать автомобиль клиента или добавить новый.
- Показать разницу "примерная цена" / "фиксированная цена".
- Расшифровка цены: подача, километры, минуты, коэффициент, опции, промокод.
- Не показывать технические данные пользователю.

### 3.4. Опции заказа

- Способ оплаты: наличные, карта, СБП, корпоративный счет.
- Промокод и бонусы.
- Комментарий водителю.
- Детское кресло, багаж, животные, кондиционер, тихая поездка.
- Для трезвого водителя: коробка передач, тип авто, место парковки, доверенность/нюансы.
- Подтверждение заказа одной крупной кнопкой.

### 3.5. Поиск водителя

- Экран остается картой с bottom sheet.
- Состояния: ищем водителя, расширяем поиск, водитель найден, не нашли водителя.
- Видимый cancel с причинами отмены.
- Во время поиска можно менять оплату/комментарий, если backend поддерживает.
- Если водитель не найден: предложить другой тариф, поднять цену, повторить поиск.

### 3.6. Водитель назначен

- Карта показывает водителя в реальном времени.
- Карточка: имя, рейтинг, авто, номер, цвет, ETA, тариф.
- Кнопки: позвонить, чат, отменить, безопасность.
- Push: "Водитель назначен", "Водитель подъезжает", "Водитель на месте".
- Для трезвого водителя: карточка исполнителя и чеклист передачи авто.

### 3.7. Поездка идет

- Карта следует за маршрутом.
- Bottom sheet: ETA, текущий адрес, финальная точка, водитель, безопасность.
- Кнопки: чат, звонок, поделиться поездкой, экстренная помощь.
- Возможность изменить точку назначения, если backend поддерживает пересчет.
- Для трезвого водителя: этапы "встретился", "принял авто", "едем", "припарковал", "передал авто".

### 3.8. Завершение поездки

- Экран завершения без скролла на маленьком телефоне.
- Цена, способ оплаты, чек, маршрут.
- Оценка водителя 1-5.
- Теги: чисто, быстро, вежливо, опасное вождение, опоздал.
- Чаевые, если оплата картой.
- Жалоба/поддержка.
- Кнопка "Готово" видна сразу.

### 3.9. Профиль пассажира

- Личные данные.
- Способы оплаты.
- Автомобили клиента для услуги "трезвый водитель".
- Адреса: дом, работа, избранное.
- История поездок с повторами маршрута.
- Чеки и квитанции.
- Бонусы, промокоды, реферальная программа.
- Поддержка и обращения.
- Настройки уведомлений.
- Правовые документы.
- Удаление аккаунта и выгрузка данных.

## 4. Приложение водителя: полное ТЗ

### 4.1. Авторизация и регистрация

- Вход по телефону OTP.
- Анкета водителя.
- Загрузка документов: паспорт, права, фото, авто, СТС, страховка.
- Банковские реквизиты/самозанятый/налоговый статус.
- Статусы модерации: черновик, на проверке, нужны правки, одобрен, заблокирован.
- Экран причины отказа и повторная отправка.

### 4.2. Главный экран водителя

- Полноэкранная карта.
- Большой переключатель "На линии / Не на линии".
- Баланс/заработок за смену.
- Ближайшие зоны спроса.
- Текущий тариф и доступные классы.
- Предупреждения: плохой GPS, нет интернета, низкий заряд.
- Кнопка поддержки и безопасности.

### 4.3. Входящий заказ

- Bottom sheet поверх карты.
- Таймер принятия заказа.
- Цена, расстояние до подачи, примерная длительность, тариф.
- Адрес подачи и район назначения.
- Опции клиента: багаж, животные, комментарий, трезвый водитель.
- Кнопки: принять, отклонить.
- Отклонение с причинами, если требуется.
- Haptic/звук для нового заказа.

### 4.4. Активный заказ

- Этап 1: еду к клиенту.
- Этап 2: приехал, ожидание.
- Этап 3: начал поездку.
- Этап 4: завершил поездку.
- Все основные кнопки должны помещаться на маленьком экране без критичного скролла.
- Навигационная карта занимает верх, action sheet занимает низ.
- Кнопки всегда очевидны: "Приехал", "Начать", "Завершить".
- Вторичные действия в меню: чат, звонок, отмена, история, замена маршрута.
- Таймер ожидания виден без прокрутки.
- Для трезвого водителя: этапы приемки/передачи автомобиля.

### 4.5. Навигация водителя

- Маршрут до клиента и до точки назначения.
- ETA и дистанция.
- Автоматический reroute при отклонении.
- Текущая скорость и GPS-точность.
- Предупреждение при потере геолокации.
- Быстрый переход во внешнюю навигацию: Яндекс Навигатор, 2ГИС, Google Maps.
- Без placeholder-карты в production.

### 4.6. Деньги и история

- Заработок за день, неделю, месяц.
- Комиссия сервиса.
- Чаевые.
- Наличные/безнал.
- Выплаты и статус выплат.
- История заказов.
- Детализация каждого заказа.
- Рейтинг и причины снижения рейтинга.
- Бонусы и цели смены.

### 4.7. Профиль водителя

- Данные водителя.
- Документы и сроки действия.
- Автомобиль/доступные услуги.
- Настройки уведомлений.
- Поддержка.
- Правовые документы.
- Обучение и правила сервиса.
- Блокировки/предупреждения.

## 6. Backend: полное ТЗ

### 6.1. Основные домены

- Auth: OTP, refresh token, device sessions.
- Users: clients, drivers, admins.
- Orders: lifecycle, quote, dispatch, cancel, rate, chat.
- Geo: geocoding, route, ETA, driver location.
- Tariffs: pricing rules.
- Payments: intents, webhooks, receipts, refunds.
- Push: FCM/APNs events.
- Support: tickets, messages, attachments.
- Admin: moderation, manual actions, audit.
- Analytics: metrics and logs.

### 6.2. Жизненный цикл заказа

- `draft`
- `quoted`
- `searching`
- `driver_assigned`
- `driver_accepted`
- `driver_arriving`
- `driver_arrived`
- `waiting`
- `in_progress`
- `completed`
- `cancelled_by_client`
- `cancelled_by_driver`
- `cancelled_by_dispatch`
- `payment_pending`
- `paid`
- `payment_failed`

Каждый переход должен быть валидирован backend-ом. Клиент и водитель не должны вручную переводить заказ в невозможный статус.

### 6.3. Dispatch

- Поиск ближайших доступных водителей.
- Фильтр по тарифу, услуге, рейтингу, авто, документам.
- Очередь предложений заказа водителям.
- Таймер принятия.
- Повторное назначение при отказе/таймауте.
- Dynamic pricing при высоком спросе.
- Защита от двойного принятия заказа.

### 6.4. Realtime

- Socket.IO/WebSocket для:
  - статуса заказа;
  - геолокации водителя;
  - чата;
  - входящего заказа водителю;
  - отмены;
  - оплаты;
  - админской карты.
- Reconnect logic на клиентах.
- Push как fallback, если приложение свернуто.

### 6.5. Безопасность

- JWT/refresh rotation.
- Rate limit на OTP, login, quote, create order.
- Device fingerprint.
- Audit log для денег и админских действий.
- RBAC для админки.
- Маскирование телефонов.
- Политика хранения персональных данных.
- Удаление аккаунта и данных по запросу.

## 7. Дизайн-система

### 7.1. Общий стиль

- Свой бренд "Короли дорог": премиальный, быстрый, городской, не копия Yandex.
- Темная/светлая тема, но основная должна быть читаемой на улице.
- Контрастные CTA.
- 8pt сетка.
- Радиусы 8-16 px в зависимости от компонента.
- Единые токены цветов, типографики, отступов, теней.
- Все состояния: normal, pressed, loading, disabled, error, success.

### 7.2. Компоненты

- Fullscreen map layout.
- Bottom sheet: collapsed, half, full.
- Drag handle.
- Primary/secondary/destructive buttons.
- Floating action buttons на карте.
- Address search field.
- Tariff carousel.
- Driver card.
- Trip status card.
- Payment selector.
- Chips для опций.
- Modal для отмены/подтверждения.
- Toast/snackbar только для вторичных событий.
- Skeleton loaders.
- Empty states.
- Error states.

### 7.3. Жесты и движения

- Swipe up/down для bottom sheet.
- Horizontal swipe тарифов.
- Tap на карту для выбора точки.
- Long press для pin.
- Haptic feedback на принятие заказа/подтверждение.
- Плавные переходы 200-300 ms.
- 60 fps при скролле и движении карты.
- Никаких тяжелых анимаций в списках, если они вызывают лаги.

### 7.4. Маленькие экраны

- Все primary action должны быть видны без прокрутки.
- На активном заказе/поездке карта может быть меньше, но кнопка действия всегда видна.
- Bottom navigation не должен перекрывать контент.
- SafeArea обязателен снизу и сверху.
- Никаких черных полос, пустых блоков и обрезанных элементов.

## 9. Acceptance criteria для "full release"

Продукт можно считать готовым, когда:

- Пассажир может пройти весь путь от входа до оплаты и оценки без mock-данных.
- Водитель может пройти весь путь от входа до завершения заказа без mock-данных.
- Админ видит заказ, клиента, водителя, платеж и историю событий.
- OTP работает через реального SMS-провайдера.
- Push работает на Android и iOS.
- Оплата работает через реального провайдера и webhook.
- Все карты живые, без placeholder-экранов в основных сценариях.
